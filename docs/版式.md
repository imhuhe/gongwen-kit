## 踩过的坑（共同点：全是静默故障）

1. **lvlRestart 的位置**：条文体「第X章／第X条」全文连号靠 `<w:lvlRestart w:val="0"/>`，
   它在 schema 里必须排在 `numFmt` 之后——位置不对 Word 不报错，而是整份编号不显示。
2. **compressPunctuation**：docx 库不写 `characterSpacingControl`，缺了它标点压缩失效，
   同样 28 字一行的断行位置会差一个字。在 writeDoc 的 settings 补丁里补。
3. **浮动框架锚点必须用 margin**（对照实验：`vAnchor=text` 根本不浮动、
   `vAnchor=page` 会沉到页边距以下，只有 `margin` 正好压在版心下边缘）。
   版记的「末条线与版心下边缘重合」靠 framePr 的 `vAnchor=margin` + `yAlign=bottom`。
4. **framePr 逐字段一致才并框**：版记各段落的 framePr 必须完全相同，
   Word 才合并成一个浮动框架；有一处不同就各起一框、互相叠压。
5. **样式 firstLineChars 压过段落 hanging**：Normal 样式带 `firstLineChars=200`
   （正文两字缩进），段落缩进与样式逐属性合并时它压过 hanging——抄送行首会被
   顶到 6 字位。凡用 hanging 的段落必须显式 `firstLineChars: 0`。
6. **Word 右对齐时行尾空格悬空、不计宽度**：用补空格做对齐不成立，
   要定位用制表位（签发人回行对齐就是这么实现的）。
7. **两个 docx 模块实例**：稿源脚本不在本仓目录下跑时，自己 `require("docx")`
   会解析出第二份实例，段落序列化成 `<rootKey>w:p</rootKey>`、产出打开是空的。
   一律用 `G.require_docx()`。
8. **结构检查必须排在机检之前**：漏写 `...` 展开时 docx 序列化成 `<0/>`，
   按文本抽取的机检全部放行，而 Word 打不开。writeDoc 里两层兜底：
   打包前查文档树、写盘后逐 XML 部件查 well-formed。
9. **jszip 默认不压缩**：写盘补丁重打包时要用 `compression: "DEFLATE"`，
   否则文件体积涨回数倍。
10. **版心来源是 twips 不是毫米**：37mm 换算出来是 2097，权威值是 2098。
    差 1 twip 无意义，但两个数并存就要有人判断哪个算数——抄权威值，省掉这个判断。
11. **上边框的双线次序与样式名相反**：Word 把 `thickThinSmallGap` 画在上边框时是上细下粗，
   `thinThickSmallGap` 才是上粗下细。信函的两条双线按量测结果取样式，`measure-xinhan.py` 查次序。
12. **页眉里的框架会把正文顶下去**：首页页眉放了绝对定位框架，正文从页眉范围的底边起排，
   不从版心上缘起排；而且 exact 行高低于约 100tw 的空段 Word 不认（47tw 与 95tw 量出同一位置），
   线下的 7/8 字高要用首行段前距补。
13. **标志降字号后字形下沉**：机关名过长时标志按 2pt 步降字号，行高不变，字形在定高行里往下沉，
   每小 1pt 约沉 20.4tw（13 字的纪要标志降到 34pt，未补偿时落在 35.77mm）。版头空段与信函标志框架
   都按字号差同步上移抵掉，常数是 `MARK_SINK_TW_PER_PT`。补偿后空段不足 100tw 时改用标志段的段前距（坑 12）；
   套打不画字形，不补。联合行文的标志表格另有一个与字号无关的偏差（约高 0.69mm），由 `JOINT_PAD` 补。
   已知限制：份号、密级、紧急程度三项都有，标志又降到二号时，上方已无空可让，标志落在约 37.6mm。
14. **量测要用本机实有的标题字体**：本机没装方正小标宋时 Word 静默回退到 SimSun，
   字形 ascent 不同，标志位置差约 3mm，量出来的数不能作数。没装就设
   `GONGWEN_FONT_TITLE="Songti SC Black"` 出量测件；`tools/check-pdf.py` 会把标题回退报出来，
   两个量测脚本遇到回退字体直接拒绝出数。信函的首版校准就是在回退字体上量的，换成 Songti 后
   标志高了 2.57mm；降字号时字形变矮，第一条双线要另按 `RULE1_SHRINK` 上移。

## 量测方法

改完版式跑一轮：

```bash
# 量测脚本需要装了 PyMuPDF 的 Python（pip install pymupdf / uv run --with pymupdf）
export GONGWEN_FONT_TITLE="Songti SC Black"   # 本机没装方正小标宋时（坑 14）
node templates/notice.js && node templates/gongwen-qingshi.js && node templates/jiyao.js
# 导 PDF（用 Word 导出）
python3 tools/measure-letterhead.py <pdf>
python3 tools/measure-banji.py <pdf>
python3 tools/measure-xinhan.py <信函 pdf>
```

数值落在上表「量测结果」附近（±0.5mm）才算过。页码那条目前用渲染图扫描，
扫码在任务记录里；日常改动落在这两个脚本覆盖的面上。
