# 发布检查

本文件是 0.4.x 的发布清单；命令在仓库根目录执行。

## 1. 代码与测试

```bash
git status --short                  # 必须干净
node -e 'console.log(require("./package.json").version)'
npm ci
npm test
```

`npm test` 必须全部通过；不要用 `--allow-dirty` 发布。

## 2. CI 矩阵

`.github/workflows/ci.yml` 在 GitHub Actions 上跑：

- OS：ubuntu-latest、windows-latest、macos-latest
- Node：18、20、22
- 步骤：`npm ci` → `npm test`

发布前确认最近一次 main 的 CI 全绿。WPS 的真实打开/渲染不在 CI 覆盖范围，需要人工抽检。

## 3. 离线包

```bash
node tools/pack-offline.js --out /tmp/gongwen-offline
cd /tmp/gongwen-offline
tar -xzf gongwen-kit-v<版本>-offline.tgz
node gongwen-kit-v<版本>/bin/gongwen.js where
```

再解压目录里跑一次：

```bash
node .../bin/gongwen.js new --form wen --out /tmp/发布自检.js
node /tmp/发布自检.js
```

确认三检通过。离线包约 2 MB，不含样张 PDF、图片和测试。

## 4. 样张 PDF

生成侧改动（字体、落款、页边距等）才需要重导；0.4.4 不需要。

```bash
GONGWEN_FONT_TITLE="Songti SC Black" node templates/notice.js ...
```

用 Word 导出 `docs/样张` 的通知、请示、信函、企业内部报告，跑：

```bash
/Users/huanghe/.venvs/pdf/bin/python tools/check-pdf.py docs/样张/公文通知.pdf
```

落款页用 PyMuPDF 量署名/日期中心，差异应小于 1pt；`assets/qiye.png` 同步重做两页拼图。

## 5. 真实路径

- Claude Code：开新会话，确认 `~/.claude/skills/gongwen-kit` 指向 main，跑一次真实公文
  （起稿 → 出稿 → 三检 → 可选 fix）。
- DeepSeek Harness：新会话加载 `gongwen-kit` skill，跑一次起稿/出稿/三检。
- 旧会话可能缓存旧 `SKILL.md`，一定要新会话。

## 6. 打标签与推送

只在代码、测试、离线包、样张、真实路径都通过后：

```bash
git tag -a v<版本> -m "gongwen-kit <版本>"
git push origin main --tags
```
