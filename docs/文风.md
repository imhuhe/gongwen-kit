# 文风：两层判据与词表怎么改

## 两层，分法只有一条

| 层 | 依据 | 判法 | 住在哪 |
|---|---|---|---|
| 规范层 | 国家标准 | 命中即错，不看语境 | `checks/style-scan.js` 内建两类 |
| 风格层 | 词表（意见） | 只提示，不拦稿 | `data/style-words.tsv` |

规范层两类：**异形词**（GF 1001—2001，`data/yixingci.tsv`，93 组机检 + 32 组留档）、
**中文里的半角标点**（GB/T 15834）。风格层：AI 套话、商业黑话、空词、表演腔
（词表扫描），加几种形状（否定平行句成堆、AI 工具指纹、拉丁缩写、情态堆叠、
虚动词结构）。

把风格包装成规范是这套体系最不能犯的错：清黑话的依据只能是「偏好」，
不能是「国家不让」——第一次被人反驳，整套检查都会失信。

## 怎么加自己单位的口径词

`data/style-words.tsv` 直接续行，格式：

```
淘汰说法 <TAB> 改成 <TAB> 分组 <TAB> 档位
```

档位 `strict` 会被扫、`loose` 只留档供查。改完下次出稿即生效，不用动代码。

## 校准办法（表头有完整记录）

词表是意见，意见要有出处。每条目在语料上过一遍：

- **零误报门槛**：抽命中人工逐条看，有一条是正当用法就降级或移除；
- **命中自家语料就降级**：词表跟着语料走，不跟着想象走。

当前默认表在约 1.27 万字公文语料（三份样张 + 一份真实业务方案 +
一篇中国政府网公开文件「国办发〔2026〕11 号」）上校准过：真公文里出现的
「抓手」「赋能」「与此同时」，以及机关与央国企的标准用语（降本增效、提质增效、
倒逼、综上所述、由此可见等）已全部移出扫描档。逐条理由见
`data/style-words.tsv` 表头。

## 三条方法论

1. **负面词表不进提示词**：词表一旦进上下文，模型会写出「本段未使用某某」
   来呼应它——规则本身催生了它要消除的噪音。词表只住在扫描器里。
2. **零误报优先**：报一条假阳性比漏一条真阳性更伤——假阳性多了，人会开始
   扫读机检输出，整套检查跟着贬值。`check-doc` 里靠标签/对齐判断的规则
   （我司、GDP、斜体、数值列非数值）同样只提示不拦稿。
3. **改完不解释**：按提示改了字就把字改掉，不写「已按规范调整」。

## 扫描范围与独立使用

出稿时自动扫 `.docx` 正文。「」、“”、《》里的引文/书名、网址、邮箱、文件名
（`公文.docx`）与裸域名（`中文.com`）一律豁免——那里的标点不是句子标点，是词的一部分。
机检与修复共用 `lib/text-guard.js` 的保护范围；规范层词表（`data/yixingci.tsv`）缺失时
`check-style` 以 2 退出，不能静默给出「文风通过」。
也可以独立扫任意文件，当体检用：

```bash
node checks/check-style.js 某文件.docx --strict   # 也接受 .txt / .md
```

手写的稿子、别处来的稿子都可以拿它体检——不只是本工具生成的文件。
